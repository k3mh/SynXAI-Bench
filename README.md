# SynXAI-Data

A synthetic tabular benchmark with **instance-level ground truth**, for auditing whether local XAI
methods recover the features that actually generated a label.

Datasets are built from a library of 12 relationship rules. Each instance is generated by one rule and
carries that rule's feature set as its ground truth, so the "important" features differ from row to
row rather than being fixed globally. Generation is deterministic under a single seed.

The repository holds three things:

| | |
|---|---|
| **Generator** | `src/dataset_generation/DataSetGen_v4.py` — the 12 rules and the composite builder |
| **AFR** | `src/model_validation.py` — Additive Feature Restoration: tests that a trained model actually relies on the designed features |
| **XFA** | `src/xfa/` — a two-tier explanation-fidelity metric, a runner for four explainers, and a construct-validity battery |

## Environments

Two virtualenvs are needed; a dependency conflict forces the split. Both read the same datasets.

| Env | numpy | Used for |
|---|---|---|
| `.venv_xfa` | >= 2 | SHAP, LIME, Anchor; the XFA metric and its validation battery |
| `.venv_lore` | < 2 | LORE (`lore_sa` pins numpy<2) **and the generator** (`DataSetGen_v4` fails on numpy>=2) |

```
python -m venv .venv_xfa && .venv_xfa/Scripts/pip install -r requirements.txt
```

Pinned versions are in `requirements.txt`.

## Running

Package modules are run from `src/`:

```bash
cd src && python -m xfa.runner --tools shap,lime --budget 1000 --ndatasets 11
```

The runner loads a benchmark directory (datasets, metadata, trained models), samples correctly
predicted instances evenly across each dataset's rules, scores every explainer, and writes
per-instance metrics, the raw explanations and per-dataset roll-ups. It checkpoints per dataset, so
relaunching with the same `--out` resumes rather than restarting.

The validation battery runs the same way, one module per pillar:

```bash
cd src && python -m xfa.validation.p3_discriminant --run 1K_v2
```

See `src/xfa/validation/README.md` for how to register a new run.

Tests (needs `.venv_lore`, since the generator imports numpy<2):

```bash
python -m pytest tests -q
```

## Data

Generated datasets, trained models and audit outputs are **not** in this repository — they run to
several gigabytes. They are archived separately; see the Data Availability statement in the paper for
the DOI.

Everything is reproducible from the code: generation is seeded end-to-end, and both explainers are
reseeded per instance so two runs of the audit return bit-identical attributions.

## Layout

```
src/
  dataset_generation/DataSetGen_v4.py   generator: 12 rules, composite datasets
  model_validation.py                   AFR
  run_xai_benchmark_v2.py               driver: generate suite, train models, validate
  Experiments/Initial_experiment_v1.py  the SHAP/LIME fidelity audit
  xfa/
    metrics.py        two-tier fidelity metrics
    relevance.py      ground-truth vectors per instance
    runner.py         benchmark driver
    aggregate.py      roll-ups
    explainers/       SHAP, LIME, Anchor, LORE wrappers
    validation/       construct-validity battery (p1-p6)
tests/                guard tests for the generator, AFR and XFA
archive/              superseded scripts, kept for reference
```
